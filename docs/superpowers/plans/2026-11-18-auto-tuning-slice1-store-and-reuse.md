# `--auto` tuning, slice 1: saved-result store, key and `--auto` reuse — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Refreshed 2026-11-24 against `dev` at 6c67922e, to match the refreshed spec. What changed is listed in "Stale since 11-18" below.

**Goal:** `--auto[=profile]` on serve, run, chat and bench applies a saved tuning result when its checksummed key matches this model,
device and build, and the saved placement still fits free memory. It warns when the result is stale or partial, falls back to defaults
on a miss (printing the `dotllm tune` command to run), and reports where every setting came from. The CLI help and `docs/CLI.md`
describe it.

**Architecture:**
- A `DotLLM.Server/Tuning/` folder holds:
  - the result DTOs and their source-generated JSON context;
  - the key: model hash and modifiers, device fingerprints and scope, driver identity, perf identity, environment overrides;
  - the store: path, checksum, match;
  - the precedence-aware applier, which returns a filtered `TunedSettings` plus a source map. Each command maps that onto its own
    settings type (serve onto `ServerOptions`; run, chat and bench onto their Spectre settings).
- Serve, run, chat and bench call one entry point before the model loads.
- Producing results (`dotllm tune`) is slice 2. In this slice, files are written only by tests and by `TuningStore.Save`.

**Tech Stack:** .NET 10, System.Text.Json source generation, Spectre.Console.Cli 0.49.1, xUnit.

**Spec:** `docs/superpowers/specs/2026-11-18-auto-tuning-design.md` (#1902): Goals 2 and 6, "Saved result", "Surfaces", and items 6
and 7 of "Device memory admission".

## Global Constraints

- One issue, one branch, one PR, targeting `dev`.
  - Branch `issue/{N}-auto-tuning-store`; commits carry `(#{N})`.
  - The PR says `Closes #{N}`. Close the issue by hand after the merge.
- **Store path:** `~/.dotllm/tuning/<model-hash>/<scope>-<profile>.json`; `DOTLLM_TUNING_DIR` overrides the root.
- **Key fields and their mismatch outcome** (the spec's table is the source of truth):
  - **miss:** schema version; model hash; model modifiers; device identity (for `auto` scope, every device); scope; profile name and
    hash; KV quality budget.
  - **stale:** driver identity; perf identity (release version, kernel-file hash, kernel assembly MVIDs, .NET runtime version);
    environment-override hash; tuner protocol version.
- **Checksum:** SHA-256 over the canonical JSON of key and result, stored in the file.
- **Match outcomes:**
  - **Hit:** everything matches.
  - **Stale:** only stale fields differ. Applied, with a warning naming old and new, plus the `dotllm tune --recheck` command.
  - **Partial:** the file is marked `partial`. Applied, with a warning plus the `dotllm tune` command to finish it.
  - **Miss:** a miss field differs, the checksum fails, or the file is corrupt or absent. The defaults are used, with a warning plus
    the `dotllm tune` command.
- **Apply-time checks**, on Hit, Stale and Partial:
  - The saved placement must be admitted against free device memory now, at the context being served. If not, the defaults run and
    the warning gives required and free bytes. Never spill.
  - A setting the current build refuses (`TurboQuantKvSupport.RefusalReason`) is dropped with a warning. It is never substituted.
- Explicit flags always win over saved settings.
- `/v1/status` gains a `settings_source` map with values `flag`, `auto` or `default`.
- **JSON DTO rule (CLAUDE.md):** no initializer on any `init` property, every optional member is nullable, and the new context gets a
  `JsonContextDefaultsTests`-style guard.
- Every correctness guard is shown able to fail (mutants listed in the PR). Commit before applying a mutant.
- CPU-only test filter: `FullyQualifiedName!~DotLLM.Tests.Unit.Vulkan&Category!=GPU`.
- **Backends:** the device fingerprint covers CPU, CUDA and Vulkan together (the parity rule).
- No product behaviour changes without `--auto`.

## Review Focus

1. **A GGUF replaced in place** (same path, new content, mtime changed). This must be a miss. `BaseHash` keys on path, length and
   mtime; the test proves it through `ModelHash.Of`. Test in Task 2.
2. **An HF hub-cache file.** Take `hf:<blob id>` from the blob name before any hashing. `BaseHash` resolves link targets, and Windows
   refuses some snapshot symlinks (`ERROR_UNTRUSTED_MOUNT_POINT`), so the blob-id branch must come first. Test in Task 2.
3. **A hand-edited tuning file** with a valid shape but the wrong checksum. This must be a miss with a warning, and never an exception.
   Test in Task 3.
4. **`--auto` together with an explicit `--cache-type-k`.** The flag wins for K. V comes from the saved result unless it was given too,
   **except** when either side is TurboQuant: a mixed tq pair is refused (#1895), so the saved pair is dropped and V stays default.
   Test in Task 4.
5. **A machine with two GPUs where `--device vulkan:1` was given.** The fingerprint is for the device actually used, not device 0.
   Test in Task 2.
6. **`--device auto`.** The lookup uses the `auto` scope and the machine key. A result saved for an explicit device is not found, and
   the reverse. Test in Task 3.
7. **A saved placement that no longer fits.** Defaults run, with bytes in the warning. Test in Task 4.
8. **`--auto` followed by the model argument.** `dotllm run --auto model.gguf` must treat `model.gguf` as the model. Test in Task 5.
9. **An A/B variable set at serve time that was not set at tune time** (for example `DOTLLM_CUDA_STEP_GRAPH=0`). Stale, and the warning
   names the variable. Test in Task 3.

**Interfaces (produces):**

```csharp
public enum SettingSource { Default, Flag, Auto }
public sealed record AutoApplied(TunedSettings Applied, IReadOnlyDictionary<string, SettingSource> Sources, TuningMatch Match,
                                 IReadOnlyList<string> Warnings, string? Advice);
public delegate string? SettingRefusal(TunedSettings candidate);                        // null = runs here; else the reason
public delegate (bool Fits, long RequiredBytes, long FreeBytes) PlacementAdmission(TunedSettings candidate, int servedContext);
public static class AutoSettings {
  public static IReadOnlySet<string> ExplicitFlags(IReadOnlyList<string> rawArgs);   // canonical setting names given on the command line
  public static AutoApplied Apply(IReadOnlySet<string> explicitFlags, TuningMatch match, string tuneCommand,
                                  int servedContext, PlacementAdmission admit, SettingRefusal refuse); }
```
- **Setting names and their flags** (the dictionary keys):
  - `device` ← `--device`/`-d`
  - `gpu_layers` ← `--gpu-layers`
  - `moe_offload` ← `--moe-offload`, `--cpu-moe`, `--n-cpu-moe`, `--moe-cache-mib` (match `MoeOffloadCli`; any one of them marks the
    whole MoE group as flagged)
  - `cache_type_k` ← `--cache-type-k`/`--kv-quant-k`
  - `cache_type_v` ← `--cache-type-v`/`--kv-quant-v`
  - `paged` ← `--no-paged`/`--paged`
  - `prefill_chunk_size` ← `--prefill-chunk-size`/`--ubatch-size`
  - `mtp` ← `--mtp`/`--no-mtp`
  - `speculative_k` ← `--speculative-k`/`--draft-tokens`
  - `threads` ← `--threads`
  - `decode_threads` ← `--decode-threads`
  - `expected_concurrency` ← `--expected-concurrency`
  - `ctx_size` ← `--ctx-size`/`-c`/`--ctx`
- **Rules, in order:**
  1. A setting whose flag was given is `Flag`; `Applied` leaves it null so the command keeps the flag's value.
  2. On a Miss, nothing else is applied: every other source is `Default`.
  3. On a Hit, Stale or Partial, the non-null saved members that were not flagged are candidates.
  4. **KV pairing:** when the saved K or V is TurboQuant and either side was flagged, both saved KV members and saved `paged` are
     dropped, with a warning. A TurboQuant pair is applied whole or not at all.
  5. **Refusal:** if `refuse(candidates)` returns a reason, the KV group is dropped with that reason as a warning. Nothing is
     substituted.
  6. **Admission:** if `admit(candidates, servedContext)` does not fit, **all** saved settings are dropped (sources `Default`), with a
     warning `tuned placement needs {required}, {free} free`. A served context above `TunedContext` that still fits adds a warning
     that decode figures were not measured at that depth.
  7. What remains is `Auto`.
- **`Advice`:**
  - Miss: `"no tuning result for this model/device/profile ({reason}); run: {tuneCommand}"`.
  - Stale: `"... tuned for {old}, now {new}; re-measure: {tuneCommand} --recheck"`.
  - Partial: `"... incomplete; finish: {tuneCommand}"`.
  - Hit: `null`.
